## Modelling rules (checked by `export_all.py`, failing the export)

1. One collection per object, named exactly the `objectId` (`jingle_bell`); the hub collection is `hub`.
2. Triangles after triangulation ≤ `Config.Budgets.meshTriangles[tier]` (hub: tier-5 budget). The script
   reads the budget from a small JSON copy kept in sync by a Lune test, see "Budget source" below.
3. Flat shading (no smooth groups, no custom normals), no modifiers left unapplied, scale 1 and rotation 0.
4. Every face's UVs lie inside one swatch rectangle of the palette; exactly one material (`Palette`).
5. Origin at the bottom centre of the footprint; the longest bounding-box side in studs (1 unit = 1 stud)
   equals `ObjectDef.size` within 5 %. The script reads sizes from `art/scripts/budgets.json` (see Budget
   source).
6. "Slightly oversized, cartoonish": proportions exaggerated by about 10–20 % on the main feature (eye,
   handle, roof), judged in the Blender viewport and in the Studio capture; not machine-checked.

## Budget source (single source of truth)

`Config.luau` and `SnowVillage.luau` hold the budgets and sizes. Blender cannot read Luau, so a Lune script
`scripts/art-sync.luau` (run by hand and by `ArtManifest.test.luau` in "verify" mode) writes
`art/scripts/budgets.json` (`{ "meshTriangles": [...], "sizes": { "<id>": size }, "tiers": { "<id>": n } }`)
from those modules. The test fails when the committed JSON is stale. The Blender scripts read only that JSON.

## `export_all.py`

Run: `blender --background --python art/scripts/export_all.py -- --out art/export`. For each `.blend` in
`art/source`, each object collection: validate rules 1–5; duplicate, triangulate; count triangles; export
FBX (`apply_unit_scale`, axis forward `-Z`, up `Y`, mesh only, no animation, no lights/cameras); compute
`bytes` and `sha256`; append to the manifest. Output ordering is by `id` so reruns give identical files for
unchanged sources. Exit code ≠ 0 on any rule violation (printed with the object name).

## Manifest and the check step

Schema in [data-model.md](../data-model.md) §10. `scripts/check.sh` needs **no new step** for this: the
check is `ArtManifest.test.luau`, which runs in the existing "Lune unit tests" step. It reads `art/export/manifest.json`, the
`SnowVillage` objects, `Config.Budgets` and the budgets JSON, and asserts: one entry per object plus `hub`;
`triangles ≤ budget[tier]`; each `bytes` equals the file size read with `fs`; each `sha256` equals the hash
the test computes with `@lune/serde`'s `hash` (no hand-written SHA-256 helper), so CI needs nothing new.
A second assertion scans `src` (excluding `Assets.luau`) for `rbxassetid://` and `rbxasset://sounds`
and fails on any hit (FR-007). The "require ids" mode is the environment variable `REQUIRE_ASSET_IDS=1`: the test then
also fails on any empty string in `Assets.meshes` and `Assets.palette`; the final task sets it in
`scripts/check.sh` permanently once the owner's import is done.

Note for the implementer: confirm `serde.hash` supports `sha256` in Lune 0.10.5 in T001; if not, the
fallback is `shasum -a 256` run from `check.sh` into a temp file that the test reads.

## Import hand-off (owner session, finding F-4)

1. Agent: run `export_all.py`; commit `art/export`; state in the PR which ids are new.
2. Owner, in Studio: Asset Manager → Bulk Import → select `art/export/*.fbx` and `art/palette.png`. Accept
   defaults except: no script/anim import; Mesh scale 1.
3. Agent (Studio MCP, claimed): read the imported `MeshPart.MeshId` values by file name through
   `execute_luau` (`AssetManager` is not scriptable; the importer drops parts into `Workspace` or a folder the
   owner names, and the agent reads `MeshId`, `TextureID`), then writes `Assets.meshes` and `Assets.palette`.
4. Agent: delete the imported parts from the place (they must not ship as place content), run the Studio
   spec that compares each template's size with `ObjectDef.size` and counts scripts in templates (zero).

If step 2 cannot happen before the 004 PR, the PR merges with the procedural fallback and
`REQUIRE_ASSET_IDS` off; the plan marks Feature 004 "art pending" and the owner runs the session before 004d.
