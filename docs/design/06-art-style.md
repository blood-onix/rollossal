# Art style: how realistic

The first draft used the current pipeline's toy look: chunky, flat-shaded, oversized features. For a 16+ launch audience that reads as a kids' game in the thumbnail. The recommendation is **stylised real**: real proportions and real detail, still on one shared texture, so phones keep 30 fps and a season is still one texture swap.

## The three options

| | A. Toy low-poly (current) | **B. Stylised real (recommended)** | C. Realistic PBR |
| --- | --- | --- | --- |
| Looks like | A wooden toy town | A real city with simplified, clean surfaces | A photo-ish city |
| Proportions | Chunky, features +10–20 % | Real-world, the hero feature at most +10 % | Real-world |
| Shading | Flat faces, one colour per face | Bevelled edges, smooth round parts, gradient shading baked into the atlas | `SurfaceAppearance` with colour, normal, roughness and metalness maps |
| Textures | One 256 px palette | One 1024 px gradient atlas plus trim detail, shared by every prop | Up to 4 maps per prop type, about 70 types |
| Memory | Lowest | Low: one texture for the whole city | High: phones drop texture quality or run out of memory |
| Season swap | Swap the palette | Swap the atlas (regenerated by script per theme) | Re-author every texture per season |
| Triangles (tiers 1–5) | 300 / 300 / 800 / 2,500 / 2,500 | 500 / 700 / 1,500 / 3,500 / 5,000 (proposed) | Similar to B, plus normal maps |
| Tone risk | Childish | Funny: real things, absurd scale | "Ball eats a real bus" starts to look like destruction |
| Verdict | Too young for 16+ | **Use this** | Not for a phone-first Roblox game |

The PropCard and StyleCompare previews show A, B and C side by side.

## Stylised real, the rules

- **Real proportions.** A hatchback is car-shaped, a hydrant is hydrant-shaped. Exaggerate only the one hero feature (the donut on the truck, the tube guy's arms), at most 10 %.
- **Bevel the silhouette.** One bevel segment on outer edges (about 4–8 % of the object's size). Bevels catch the light, and nothing reads as "real object" faster.
- **Smooth round things, sharp hard things.** Smooth shading on cylinders and spheres (cans, tyres, cones, the ball), sharp edges on boxes (buildings, vending machines). Export the split normals in the FBX.
- **The gradient atlas.** One 1,024 px texture per theme, generated by script from the `w-*` tokens:
  - Top half: the 64 palette cells, each 128 × 64 px, as a vertical gradient from about +12 % lightness at the top to −15 % at the bottom. Where a face's UVs sit in the cell picks its shade: tops of objects high in the cell, undersides low. That bakes in ambient occlusion without lightmaps.
  - Bottom half: eight trim strips, 1,024 × 64 px each, drawn in role colours: grille, vent slats, tyre tread, window frame, brick course, panel seams, kerb stone, wood grain. No words, no logos.
  - Every face's UVs stay inside one cell or one trim strip, and each mesh keeps one material.
- **Real-world colour.** The `w-*` roles stay, but facades, asphalt and metals sit slightly desaturated so the `w-accent-*` heroes pop. The accents carry the fun.
- **Grime is a shade, not a texture.** Darker gradient rows at the bottom of walls and vehicles, never dirt maps or decals.
- **Light the scene, not the props.** `Lighting.Technology` ShadowMap with a warm sun and `Atmosphere`, one `ColorCorrection` per theme; Future lighting only if the reference phone capture still holds 30 fps.
- **LOD for free.** `RenderFidelity = Automatic` on every MeshPart, so Roblox swaps in simpler meshes at distance. Combined with `cullTierDelta` that keeps the on-screen triangle count in check.

## What it costs

- **Constitution XI** says assets "MUST be low-poly and flat-shaded" and share one palette texture. Stylised real stays low-poly with one shared texture, but **smooth shading needs an amendment** (owner approval).
- **`Config.Budgets.meshTriangles`** goes from 300 / 300 / 800 / 2,500 / 2,500 to the proposed 500 / 700 / 1,500 / 3,500 / 5,000 (owner approval). Measure it in a Studio capture on the reference phone (MicroProfiler, Stats) with Downtown at full density before locking the numbers; the target is 30 fps with 12 balls on screen.
- **The art pipeline** changes in three checks: `export_all.py` allows split normals, the UV rule becomes "inside one atlas cell or trim strip", and `palette.py` becomes the atlas generator (reading every theme from the tokens). The Blender MCP recipes add one bevel modifier, applied before export.
- **Time per prop** goes up roughly 1.5–2×. The kit's reuse (one asset set for six themes and every future city) is what pays for it.
